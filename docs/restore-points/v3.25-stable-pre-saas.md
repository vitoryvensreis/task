# Ponto de restauração oficial — pré-SaaS

Este documento registra o estado estável do TaskEsc imediatamente antes do início da conversão para SaaS/multi-tenant.

- Commit estável da aplicação: `c0de7a89f4a7604a740debb55dcbf21b5d9dde70`
- Branch de segurança: `restore/v3.25-stable-pre-saas`
- Tag esperada após o workflow: `v3.25-stable-pre-saas`
- Versão do aplicativo: TaskEsc v3.25

## Conteúdo do snapshot

O workflow do commit que registra este ponto executa **antes de atualizar a VPS**:

1. identifica o commit exato que está rodando em produção;
2. exporta o banco MySQL/MariaDB usando `mysqldump` ou `mariadb-dump`;
3. valida o arquivo comprimido com `gzip -t` e uma checagem mínima de conteúdo;
4. gera SHA-256 do backup;
5. cria um ZIP do código exatamente no commit de produção;
6. cria a tag `v3.25-stable-pre-saas` apontando para esse commit;
7. guarda banco, checksum, manifesto e ZIP como artifact privado do GitHub Actions por 90 dias;
8. mantém uma cópia do dump em `storage/backups/` na VPS.

## Regra de restauração

Se a migração SaaS causar uma falha grave, a referência de retorno é a tag/branch acima. O banco deve ser restaurado usando o arquivo do artifact `taskesc-restore-point-v3.25-pre-saas` correspondente a este ponto.

Nenhum dump de banco, credencial ou arquivo `config/config.php` deve ser commitado no repositório.
